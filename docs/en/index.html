How it works

Three steps from check to report

01

Turn on the check and work as usual

Click “▶ Start check” or Ctrl+Shift+Q. As soon as an error appears in the console or a request fails, the extension saves it as a separate item by itself: a screenshot at that moment, the error text, the request with the server response and your actions before it.

  • Repeats of the same error are counted, not duplicated
  • Errors of third-party scripts and services are not saved, an unwanted one can be ignored (🙈)
  • Passwords, card numbers and CVV are not recorded
02

See a problem — mark it

Choose a tool on the panel at the bottom of the page. Each remark is a separate item: a screenshot with a highlight and your text, no extra logs. Need to show a scenario — turn on video recording, and events and requests will be attached to it.

Export the finished report

Click “✓ Done”. The report is a list of items in order: errors, remarks, recordings. Each has only its own data. Export: Word, Markdown, HTML, HAR or everything in one archive.

Report items

Three kinds of items — each with only the data it needs

Each item has its own severity — from 🔴 blocker to ⚪ trivial; for errors it is chosen automatically. The report does not turn into a dump of logs. A layout remark is just a screenshot and text. An error is everything the developer needs to fix it. A recording is the video and everything that happened during it.

⚠Error — automatic

A console error or a failed request → an item by itself: a screenshot at that moment, the error text, the request with body and server response, actions before the error, the console and requests around it.

💬Remark — you mark it yourself

Element, arrow, area or note → a screenshot with a highlight, your text and voice. No technical logs — they are not needed here.

🎬Recording — when you turned on video

Tab video plus actions, events, requests and console during the recording and 1–2 minutes before it.

Tester tools

Regression with one button and edge cases without the backend

🤖

Autotests from a recording

Click “Record autotest” and go through the scenario: clicks, typing, selection. Add ✓ checks — “text appeared”, “URL contains /success”. Save it — and run all scenarios after every release: what passed, what failed, at which step, with a screenshot.

🎭

Export to Playwright

Every scenario downloads as a ready .spec.ts test with a config — developers plug it into CI. Console errors count as a failure, just like in the extension.

🔌

API tests from Swagger and Postman

Import a specification — the extension checks every endpoint by itself: valid, incomplete and invalid data, no token, non-existent objects, “create → get → update → delete” chains and wrong request order. The result is “what is wrong with the API” with explanations: 500 crashes, accepting broken data, schema mismatches, leaks, access without authorization.

🧪

API response mocking

Error 500, 401, an empty list, a 5-second delay, “no network” — for any request. You can take the real response and edit it. Mocked requests are marked in the report so they are not mistaken for a bug.

📶

Slow network and a weak phone

3G, slow 3G, offline; CPU 4–6 times slower; iPhone, Android, iPad. The conditions are recorded in the report for every item.

📐

Screenshots on every screen

One button — the whole page at 375, 768, 1280 and 1920 px wide, as items in the report. You see at once where the layout broke.

🩺 Auto-check

A site audit while you test

Every opened page is checked by itself, in the background. The report has scores by area and a list of what to improve: severity, why it is bad, how to fix it and the specific elements.

  • SEO: noindex and a closed robots.txt, title and description (missing, length, duplicates across pages), h1, canonical, viewport, Open Graph, schema.org, favicon
  • Load speed: render-blocking resources, no compression or caching, heavy JS, fonts without font-display, lazy loading of images, HTTP/1.1, third-party services
  • Semantics and forms: clickable divs instead of buttons, placeholder links, buttons without type in forms, email/phone fields with type="text"
  • Practices and security: broken links and resources, HTTPS and mixed content, security headers, deprecated APIs
  • Network: duplicate requests, repeated form submissions, N+1, too frequent polling, slow and heavy responses
  • Unnecessary re-renders on any site: elements recreated without changes, empty DOM updates, constantly changing areas; for React — also a per-component counter
  • Accessibility: the axe-core engine (as in Lighthouse) with descriptions in the interface language — alt, field labels, contrast, structure
  • Images: pictures many times larger than on screen, and heavy files
  • Warnings: missing key in lists, update after unmount, infinite loops
  • Performance: Web Vitals, freezes, slow clicks

The auto-check report can be downloaded separately and handed to a developer or an SEO specialist.

Install

Two minutes, without the extension store

  1. Download the archive and unpack it to a permanent folder.
    Download qa-bug-recorder.zip
  2. Open chrome://extensions and turn on “Developer mode” in the top right.
  3. Click “Load unpacked” and choose the qa-bug-recorder folder.
  4. Pin the 🐞 icon to the browser toolbar and reload the tabs of the site under test.

FAQ

FAQ

Does the extension slow down the site?

Practically not. Console and request interception are light wrappers over standard functions, DOM changes and renders are counted in batches once a second, and data is kept only for the last few minutes. Video is recorded only when you turn it on.

How does the extension find unnecessary re-renders?

For any site — by HTML changes: if an element is removed and inserted again with the same content, or the same value is written to an attribute, that is unnecessary work for the browser. For React, component renders are counted as well — through the same mechanism React DevTools uses. Works on sites with React 16–19, including production builds. If you have the React DevTools extension installed, turn off “Count React re-renders” in the QA Bug Recorder settings: two counters interfere with each other.

Which languages does the extension support?

Chinese, English, French, German, Kazakh, Portuguese, Russian and Spanish. The language is chosen automatically from the browser language or manually in the extension settings. Reports are generated in the chosen language too — handy if bugs are read by colleagues or a client abroad.

Where does the data go during AI analysis?

Only to the service you chose (Claude, OpenAI or another) and only when you press 🤖. The key is stored in your browser. Tokens, cookies and passwords in requests are masked before sending, and sending the screenshot can be turned off. Without a key the button copies a ready prompt so you can paste it into a chat manually.

How do I connect Google Docs?

Without setup the “Google Docs” button copies the report and opens a new document — all that is left is to press Ctrl+V. One-click export needs a Client ID from Google Cloud: someone on the team creates it once following the step-by-step guide in “🔌 Integrations”. The extension only gets access to files it created itself.

Why is the buffer empty?

Collection starts when the page loads. After installing the extension, reload the site tab (F5). On chrome:// service pages and in the Chrome extension store, Chrome does not allow extensions to work.

Why does Chrome ask for confirmation for video?

Chrome allows recording a tab only after an explicit user action. If you started a bug via the icon or a hotkey, video is turned on from the panel on the page. If you then navigated to another page, click the icon → “⏺ Video”.

How does the voice comment work?

The first time you press 🎤, a tab opens asking for microphone access: this is needed only once. The voice is recorded as a separate file and mixed into the video if it is on.

What is “Full network capture”?

A mode via the DevTools protocol: it records all resources (images, scripts, styles), CORS errors and browser warnings. Chrome shows a bar saying “An extension is debugging this browser” — that is normal. It is turned on in the extension settings.

What video format is used?

WebM (VP9/VP8 + Opus). Opens in Chrome, Firefox, VLC, the players of Windows 10+ and macOS 13+. Video is not embedded in Word: use HTML or the archive.

Can I use it in Edge, Yandex Browser, Opera?

Yes, in any Chromium-based browser version 116 or newer. Installation is the same, via the extensions page and developer mode.
